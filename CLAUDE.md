# 2DFollowTheCat2

Top-down 2D game in Unity 6 (6000.3), URP, new Input System. The Editor can be driven with the Unity CLI (`unity status`, `unity command ...`).

## How to work with me (the developer)

- Explain concepts, syntax and architecture; review my code when I ask ("check my code").
- Point out bugs with the reason and the fix, but don't edit my gameplay scripts unless I explicitly ask.
- Tooling is fine when asked: git, importing/slicing sprites, animations, project settings.

## Player architecture

One job per script:
- **Player**: wires everything, creates the states, forwards `Update`/`FixedUpdate` to the current state, owns `facingDirection` (changed only through `SetFacingDirection`). Turns `Health.OnDamaged` → Hurt (only while alive, stores `lastDamage`) and `Health.OnDied` → Dead. No game logic. Its data field is `playerData` (a `CharacterData` asset).
- **PlayerInputReader**: the only script that reads input. All input is polled by the current state in `Update` (`ReadValue`, `IsPressed`, `WasPressedThisFrame`); no input events. Each state checks only the inputs it accepts.
- **PlayerStateMachine**: plain class with `Initialize` and `ChangeState` (old `Exit` → swap → new `Enter`). Only it switches states.
- **PlayerState**: abstract base. `Enter`/`Update`/`Exit` abstract, `FixedUpdate` virtual and empty.
- **States** (`Scripts/Player Scripts/PlayerStates/`, one file each): Idle, Walk, Run, Dash, Attack, Hurt, Dead; later Interact and Ability. Dash (Space, from Idle/Walk/Run via `PlayerState.HandleDashInput()`): moves at `dashSpeed` for `dashDuration` (0.25 s = Dash clip) along `facingDirection` (Walk/Run keep it equal to the move input), reads no input itself, i-frames for the whole dash, then Idle; `dashCooldown` (0.6 s) starts in `Exit`, `canDash` checks it. Hurt: starts i-frames (`invincibleTimer`) in `Enter`, pushes along `lastDamage.direction` for its `knockbackDuration`, stays stunned for `hurtDuration` or the knockback (whichever is longer), then Idle; `Stop()` in `Exit`. Idle and Dead call `Stop()` every `FixedUpdate`. Dead: plays Dead, turns off the collider in `Enter` and back on in `Exit`; no transitions of its own (RespawnManager calls `Player.Respawn`, which goes to Idle).
- **PlayerMotor**: Rigidbody only (`Move`, `Stop`, `Teleport`). No `Update`/`FixedUpdate`, no input, speeds passed in as parameters.
- The Player requires a `Collider2D` (Dead turns it off). It is a small horizontal capsule at the feet (0.6 x 0.3, offset 0.12; top-down standard, 2026-11-15): only the feet block, so the body can overlap walls behind and Y-sorting decides who is in front. Enemies measure reach to its closest point, so to the feet.
- **PlayerAnimator**: `PlayerAnimationState` enum (own file) + switch expression to cached `Animator.StringToHash`, throws on unknown values; `SetMoveDirection` drives the MoveX/MoveY blend trees.
- **PlayerCombat**: one public method, `HandleAttack(direction)`: `OverlapCircle` into a reused `List` (a `ContactFilter2D` on the enemy layer) at `attackPoint` with the weapon's range, keeps targets inside the weapon's arc, a `HashSet` so each target is hit once per swing. Stats come from `currentWeapon`, set only by `SetWeapon` (Player passes it from `Equipment.OnEquipmentChanged`; null = empty hands → `unarmedWeapon`, the `Fists` asset: Unarmed, 1 damage, 0.8 range, not an item, not in the ItemDatabase, never saved); `PlayerAttackState` decides when.
- **Health**: the shared component (see Shared), as `player.playerHealth`. The Rigidbody has Linear Damping 8 so collision shoves fade out.
- **Wallet** and **Inventory**: components on the Player GameObject (see Loot and items).
- **PlayerInteractor**: see Interaction. Later: PlayerAbilities.
- **Equipment visuals decision** (2026-11-14): per-frame layers (below) stay. Rigging (puppet look, 3 rigs), per-item clips/override controllers (28 clips per item, sync) and anchor points (stiffer, rotation breaks Point-filtered pixel art) were rejected for a game with few weapons. Walk/Run use still carry poses (no arm swing) to keep the art cheap; revisit anchors only if weapons grow past ~10.
- **EquipmentLayerView** (`Scripts/Player Scripts/`, Player children `EquipmentLayers/WeaponBackLayer` (order body-1, `drawsBackFrames`) and `BootsLayer, ArmorLayer, HelmetLayer, WeaponLayer` (body+1..+4)): paper doll. Listens to `Equipment.OnEquipmentChanged`; in `LateUpdate` looks up the body's current sprite in `bodyFrames` (126: Idle, Walk, Run, Dash, Attack, Hurt, Death x 18, sheet order) and shows the same index from the item's `EquipmentData.layerFrames` (or `layerFramesBack` on the back layer: parts the body hides, like a club head behind the leg), copying `flipX`. Empty `layerFrames` = invisible. Optional `emptySlotLook` is shown while the slot is empty: both weapon layers use `Fists` (bare forearm/hand for Walk/Run, where the body has no forearm). Art in progress (brief: `Art/Characters/LostWanderer/EquipmentLayers_ArtBrief.md`, Astra edits the body sheets in place). Body is bare (empty hands) in all 126 frames, edited in place (slicing and sprite IDs unchanged, nothing outside the sprite rects). Wired in `TopDownV2/EquipmentLayers/`: `Lantern_<Sheet>.png` for all 7 sheets (125 frames; Dash 15 hidden) `Fists_Walk`/`Fists_Run`, `WoodenClub_Walk`/`_Run` as `_Front` (gripping forearm, layerFrames) + `_Back` (club head, layerFramesBack; the plain `WoodenClub_Walk/Run.png` are Astra's combined previews, unused) and `WoodenClub_Attack.png` (Right Attack only, body 12-17); in Walk/Run every weapon sheet carries its own forearm; item sheets are sliced per 256 x 256 cell with each pivot on the body frame's canvas anchor, so items may reach past the body's trimmed rect. Bare-body pass complete: all 126 poses on the seven original sheets now have empty hands. Body PNGs were edited in place and all changed visible pixels checked against the existing sprite rectangles. The seven Lantern_<state>.png textures under EquipmentLayers carry the recovered art, including the previously wired Idle pilot. Walk and Run share identical repairs. Recomposition checked offline: small compositing differences remain on Attack, chiefly Down frames 3–5 and Right frame 5. Full Lantern slicing/assignment and in-game verification are pending.
- Wooden Club layers (2026-11-15): Idle, Walk, Run front + back all 18/18 each, Attack only the Right row (6/18); Dash, Hurt, Death and Attack Down/Up still missing. Side Run (Right/mirrored Left) now uses the matching six side Walk club poses on both equipment layers (Run slots 48-53). The Run body animation still plays. Serialized references verified; Play Mode visibility pending.
- **Equipment** (`Scripts/Inventory/`, on the Player, `player.playerEquipment`): one `EquipmentData` per `EquipmentSlotType` (Helmet, Armor, Weapon, Boots; save order, add at the end). `startingWeapon` (Lantern) set in `Awake`; Player passes it to PlayerCombat once in `Start`. `TryEquip(inventoryIndex)` swaps with that inventory slot (`Inventory.SetSlot`), so it never needs space; `UnequipTo(slot, inventoryIndex)` (empty slot takes it, same-box equipment swaps, else refused). Event `OnEquipmentChanged(slot, item)`. ISaveable (`equipment` IDs; null = pre-v3 save, keeps starting gear). IDamageModifier: `totalDefense` (sum of worn `ArmorData.defense`) off every hit, at least `MinDamagePerHit` (1).

## Enemy architecture

Same pattern as the player (`Scripts/Enemy/`):
- **Enemy**: the hub. Creates the states, forwards `Update`/`FixedUpdate`, calls `enemyDetection.Refresh()`, turns `Health.OnDamaged` → Hurt and `Health.OnDied` → Dead. Holds `facingDirection`, `lastDamage` and the patrol route (positions captured in `Awake`).
- **EnemyStateMachine** / **EnemyState** (`Scripts/Enemy/EnemyStates/`): copies of the player versions.
- **States**: Idle ⇄ Patrol → Chase → Windup → Attack (hit, then `recoverTime`) → Chase; any → Hurt (knockback, not restarted by new hits, so no stun-lock); killing hit → Dead (colliders off, `enemyData.lootTable.DropLoot` once, `Despawn` after `destroyDelay`). Windup locks facing so the player can dodge.
- **Components**: `EnemyMotor` (`MoveTowards` without overshooting, `Move`, `Stop`), `EnemyDetection` (throttled `OverlapCircle` search, immediate loss beyond `loseTargetRange`, `Linecast` line of sight only for spotting; WispGrin's `obstacleLayers` = Default, where the Dungeon's wall outline (EdgeCollider2D) and pillar colliders are), `EnemyCombat` (body attack: range check to the target collider's `ClosestPoint`, re-checked at the moment of the hit), `EnemyAnimator` (same as `PlayerAnimator`, warns once per Animator state it is asked to play but lacks).
- Enemies attack with their body, never with `WeaponData`; their attack stats live in `EnemyData`.
- **Editor/EnemyInspector**: shows the live state, target and health in Play mode.
- **Super armor** (`EnemyData.staggerHits`, 1 = every hit): every hit does damage, only every Nth makes the enemy flinch (Hurt). WispGrin 1, King Wisp 5.
- **Special states**: Chase asks `enemy.GetSpecialState()` (virtual, null by default) before attacking; a boss overrides it.
- **KingWisp** (`Scripts/Enemy/WispBoss/`, `Prefabs/Enemies/KingWisp`, variant of Astra's `KingWispVisual`): `KingWisp : Enemy`, data `WispBossData` (a `BossData : EnemyData`: minion prefab, count, max alive, cooldown, radius, summon delay/duration). Overrides `GetReferences` (adds `EnemySummoner`), `CreateStates` (adds `KingWispSummonState`) and `GetSpecialState` (`enemySummoner.canSummon`: cooldown over and fewer than `maxMinions` alive). **EnemySummoner** (the how): an `ObjectPool<Enemy>` of minions (max `maxMinions`); `Summon()` takes them from the pool, places them in a circle, `ResetForSpawn()`. Pooled enemies: `Enemy.AssignToPool`, `ResetForSpawn` (full health, no target, Idle), `Despawn` (back to the pool, otherwise `Destroy`); `EnemyDeadState` despawns after `destroyDelay` and turns colliders back on in `Exit`. Summon: stands still, plays Spawn, `EnemySummoner.Summon()` at 0.2 s spawns `Prefabs/Enemies/WispMinion` (`WispMinionData`: WispGrin without loot, detection 8) in a circle, Chase after 0.4 s. 60 health, drops the Marble Stone (Apothecary and Town Hall both need one). Farmable; played and confirmed 2026-11-14.
- **EnemySpawner** (`Scripts/Enemy/`, Dungeon `Map/Enemies/WispSpawner`): keeps one enemy on each child spawn point (`WispPoint_1..5`, where the hand-placed Wisps stood) from one `ObjectPool<Enemy>` built from `enemyPrefab` (`Prefabs/Enemies/WispGrin`, made 2026-11-15 from the placed Wisps: WispGrinData, no patrol points), max size = number of points, so the same objects are reused. Spawns everything in `Start`; `Enemy.AssignToPool(Release)` makes `Despawn` (end of the Dead state) hand the enemy back, which frees its point and starts `respawnDelay` (20 s, `Time.time`, pauses with the game); `Update` refills empty points with `pool.Get` + position + `ResetForSpawn`. Loot drops on every death, so Wisps are farmable. Tested in Play mode through the API: spawn, despawn, the same object reused at full health; the real 20 s wait not watched.
- **BossSpawner** (`Scripts/Enemy/`, Dungeon `Enemies/BossSpawner`): in `Start` rolls `spawnChance` (1 = always) and instantiates `bossPrefab` at a random child `BossSpawnPoint` (two on the cave floor, away from both player arrivals). No boss is placed in the scene by hand; every visit rolls again.

## Shared

- **StrengthBuff** (`Scripts/Combat/`, on the Player, required by PlayerCombat): a temporary damage bonus stored as a `Time.time` end timestamp like Health's i-frames (no Update); `bonusDamage` (0 when expired), `isActive`, `timeLeft`, `Apply(bonus, duration)` (drinking again refreshes the timer, the stronger bonus wins, no stacking), event `OnBuffApplied(bonus, duration)` for a future HUD icon. PlayerCombat adds `bonusDamage` to every hit. **StrengthElixirData** (`ItemData`, `IUsable`, asset `StrengthElixir`: +1 damage for 30 s, buy 30, `PotionDrink` sound): `Use` calls `StrengthBuff.Apply`. Not saved: the buff ends on a scene change. Leather Armor (defense 3, buy 80) shows on the player through Astra's 126 `LeatherArmor_<Sheet>` frames on the ArmorLayer. Bought, drunk and worn through the game's API in Play mode (bonus 1 for 30 s, a 10 hit became 7); the armor's look on the player is not checked by eye.
- **Health** (`Scripts/Combat/`): implements `IDamageable`; `Initialize(maxHealth)` from the owner's data; events `OnDamaged(DamageData)` (before `OnDied`, also on the killing hit) and `OnDied`. I-frames: `StartInvincibility(duration)` stores a `Time.time` timestamp (never shortens running i-frames); `TakeDamage` ignores hits while `isInvincible`. **IDamageModifier** (optional, found with `TryGetComponent` in `Awake`): `ModifyIncomingDamage(amount)` runs before the hit is applied; `OnDamaged` gets the reduced amount. Only the player has one (Equipment); enemies take full damage. States decide when (player Hurt and Dash).
- `OnHealthChanged(current, max)` fires on every change (`Initialize`, `Heal`, `Load`, `TakeDamage`, before `OnDamaged`). **HealthBarUI** (`Scripts/UI/`, `HUD/HealthBar` in Core, top-left): listens to it and sets a Filled `Image`'s `fillAmount`; skips `max <= 0` (before `Initialize`). Placeholder colours until Astra's art.
- **DamageData**: readonly struct (amount, normalized direction, knockback, knockbackDuration).
- **Data (ScriptableObjects)**: `CharacterData` (maxHealth, walk/run/dash speed, dashDuration, dashCooldown, `hurtDuration` (stun after a hit; match the Hurt clip: player 0.5, WispGrin 0.3), `invincibleTimer`; enemies leave it at 0 for now; WispGrin has 6 health = 3 hits with the 2-damage weapon) → `EnemyData` (detection, patrol, body attack, windup/recover/hurt timing, `lootTable`). `ItemData` (itemName, icon, maxStack, sellPrice, buyPrice). `ShopStock` (merchant's items). `LootTable` (list of `LootDrop`: prefab, optional item, chance, min/max; spawns in a circle). `EquipmentData : ItemData` (abstract `slotType`, maxStack 1, `layerFrames`) → `WeaponData` (Weapon slot; weaponType, damage, knockback, range, arc, attackDuration) and `ArmorData` (Helmet/Armor/Boots, `defense`; LeatherArmor 3 vs Wisp hits of 10/20). `WeaponType`: `Stab` (Lantern), `Blunt` (`WoodenClub`; `Unarmed` = Fists fallback, buy 60 / sell 15, in all three shop tiers). `LanterDefault` (sell 0), `WoodenClub` and `LeatherArmor` are in the ItemDatabase. Later: attack animation per weapon type.

## Loot and items

Ported from MetrooDvania, adapted to top-down:
- **IPickable** (`Scripts/Items/`): `bool TryPickUp(GameObject collector)`; true = everything taken.
- **Pickup**: abstract base with a `CircleCollider2D` trigger (no gravity). `OnTriggerEnter2D` passes the collider's Rigidbody object as collector and destroys itself when `TryPickUp` returns true. `CoinPickup` → collector's `Wallet`; `ItemPickup` → collector's `Inventory` (stays if it doesn't fit; `Configure(item, amount)` sets item and sprite). Enemies have neither, so they can't collect.
- **Wallet** (`Scripts/Inventory/`): `coins`, `Add`, `TrySpend`, `LoseShare(share)` (death penalty), event `OnMoneyChanged(int)`. Coins are not inventory items.
- **Inventory**: `slotCount` × `InventorySlot` (item + amount, stacks up to `maxStack`); `AddItemAndReturnAccepted`, `HasItem`, `ConsumeItem`, `MoveOrMerge(from, to)` (move to empty, merge same item up to `maxStack`, swap different items), event `OnChanged`. `Split(from, to, amount)` (right-drag: half the stack, rounded up, into an empty slot or onto the same item; refused if it does not fit, never swaps).
- Assets: `Prefabs/Loot/GoldCoinPickup` (animated spin), `WispEssencePickup` and `WoodenClubPickup` (prefab only; the Dungeon test instance was removed, dev tools give items), art in `Art/Items/Loot/GeneratedPickups/`; `ScriptableObjects/Items/WispEssence`, `ScriptableObjects/Loot/WispGrinLoot` (2–4 coins, 50% Wisp Essence).

## Game state and UI

- **GameState** (`Scripts/Core/`): enum `Gameplay`, `Inventory`, `Paused`, `Shop`, `Won` (Gameplay first = default). `Won` pauses time and ignores Tab/Escape; only the win panel's buttons leave it.
- **GameStateManager**: single source of truth for the mode. Polls `inventoryPressedThisFrame` / `menuPressedThisFrame` in `Update` with a `switch (currentState)` (Tab toggles Inventory; Escape toggles Paused and closes Inventory; Tab or Escape closes Shop, which only `Merchant.Interact` opens). `Awake` resets `Time.timeScale` to 1; `ChangeState` sets it (1 in Gameplay, 0 otherwise), turns the Player action map on only in Gameplay, then fires `OnGameStateChanged`.
- **PlayerInputReader** maps: Player Actions (on only in Gameplay) and UI Actions (always on: Toggle Inventory, Toggle Pause). Maps are switched with `action.actionMap.Enable()/Disable()`.
- **UIManager** (`Scripts/UI/`, on the always-active HUD Canvas): listens to `OnGameStateChanged` and only shows/hides panels with `SetActive` (InventoryPanel in Inventory and Shop, MerchantPanel in Shop, pause menu in Paused). Content scripts never know the game state.
- **CoinCounterUI** (inside InventoryPanel): listens to `Wallet.OnMoneyChanged`, refreshes in `OnEnable`.
- **InventoryUI** (on InventoryPanel): builds `inventory.count` `InventorySlotUI` prefabs into `InventoryArea` (Grid Layout Group) in `Start` (after every `Awake`), redraws all slots on `Inventory.OnChanged` and in `OnEnable`; `Refresh` loops over the built views. Owns drag and drop: `BeginDrag`/`UpdateDrag`/`EndDrag` move the `DragPreview` (last child of InventoryPanel, Raycast Target off) and call `Inventory.MoveOrMerge`; closing the panel cancels a drag.
- **InventorySlotUI** (on the `InventorySlot` prefab): `Show(InventorySlot)` sets every field each time (icon hidden when empty, amount text only above 1). `Setup(owner, index)` makes a grid view draggable via the EventSystem drag interfaces (UI pointer events are the accepted exception to "no input events"); it only reports to its owner. Views without an owner ignore drags.
- **HotbarUI** (always visible): `HotbarSize` (const 7) views of Inventory slots 0–6, built in `Start`, redrawn on `OnChanged`. A view only (no drag target): items get there by being in grid slots 0–6. Keys 1–7 (one `Player HotbarKeys` action, 7 bindings in order; `PlayerInputReader.hotbarSlotPressedThisFrame` returns the binding index via `GetBindingIndexForControl`, -1 if none) are polled by `PlayerState.HandleHotbarInput()` in Idle/Walk/Run → `Inventory.SelectSlot` + `Inventory.UseItem(slot, player)` (the number key acts right away: `IUsable` items like `HealthPotionData` are used and one is removed; a potion at full health is kept) → `OnSelectedSlotChanged(int)` → `HotbarUI` toggles the `Highlight` glow on the `InventorySlot` prefab (warm translucent copy of the slot sprite above the background, off by default). Equipment items in the hotbar equip instead (see Equipment slots).
- **Equipment slots**: Helmet, Armor, Weapon, Boots boxes in `EquipmentArea` (`Prefabs/UI/HelmetSlot`, `ArmorSlot`, `WeaponSlot`, `BootsSlot`: variants of `Prefabs/UI/EquipmentSlot`, placed in `HUD.prefab`; an unused alternative `Prefabs/UI/Equipment/` layout set was deleted 2026-11-15), each with **EquipmentSlotUI** (`Scripts/UI/`): listens to `Equipment.OnEquipmentChanged` (Icon on, Placeholder off), reports to `InventoryUI` (owner): `OnDrop` of an inventory item → `DropOnEquipment(slot)` (left-drag only, item's own box only → `TryEquip`); dragging a worn item → `BeginEquipmentDrag`/`EndEquipmentDrag(inventoryIndex)` → `UnequipTo`; dropped elsewhere it stays worn. Hotbar keys: `HandleHotbarInput` equips `EquipmentData` (`TryEquip`), uses everything else.
- Layout: Diablo 2-style panel (paper doll on top, 1-item-per-cell grid, coins bottom-right) + always-visible 1–7 hotbar = Inventory slots 0–6.
- **HUD sizes** (Core, 2026-11-14): Canvas Scaler 1920x1080, match 0.5. InventoryPanel centred, 1150x690 at (-140, 50), scale 1; grid 5 x 4 cells of 98 (spacing 10) in the left half; equipment boxes 124. MerchantStorePanel centre-anchored right beside it (pivot left, x 465); its width follows its entries (ContentSizeFitter, padding 30, spacing 12, `ShopEntry` 86 x 86), so 4 items = 440 px, right edge at 905 of 960; 5 items would run off screen. The panel art is a Simple (not 9-sliced) image, so it stretches with the width. HotBar bottom centre, 7 x 96 slots (layout group controls size). `InventorySlot`/`ShopEntry` icons stretch 18–82% of the slot with Preserve Aspect, so icons scale with any slot size; stack amount auto-sized inside the frame's bottom-right.

## Save and respawn

Ported from MetrooDvania's Lesson 52 checkpoint save, split into one job per script (`Scripts/Save/`, `Scripts/Core/RespawnManager`):
- **SaveData** / **SlotSaveData**: plain `[Serializable]` data (`version` 4, `health`, `coins`, `inventory`, `restoredBuildings`, `equipment`, `tutorialStep`). Bump `SaveData.CurrentVersion` when the layout changes; `SaveManager` accepts versions 1..current when every ISaveable can read them (v1 = no town progress, v2 = no equipment).
- **SaveFile** (static): the only code that touches the file. JSON in `Application.persistentDataPath/save.json`; writes `.tmp` then `File.Replace` keeping a `.bak`; refuses files over 64 KB.
- **ISaveable**: `Save(data)`, `Validate(data)` (null = OK, else the reason), `Load(data)`. Implemented by `Health` (1..maxHealth), `Wallet`, `TownProgress` and `Inventory` (items saved by ID = asset name, turned back into assets by the `ItemDatabase` asset; every saveable `ItemData` must be in `ScriptableObjects/Items/ItemDatabase`).
- **SaveManager** (on `SaveSystem`): collects the player's `ISaveable`s and its own object's (`TownProgress`) in `Awake`, loads in `Start` (`loadOnStart`), F5/F9 debug keys via `PlayerInputReader` (UI map: `Save Game`/`Load Game`). Validates every saveable before loading any, tries `.bak` if the main file is bad; never saves or loads a dead player. Context menu: Delete Save File.
- **RespawnManager** (on `SaveSystem`): on `Health.OnDied` waits `respawnDelay` (scaled time, pauses with the game), `Wallet.LoseShare(coinLossOnDeath)` (0.25), `Player.Respawn(spawnPoint)` (`PlayerMotor.Teleport`, full health, i-frames, Idle), then saves so the penalty sticks.
- Position isn't saved: loading keeps the player where they are; respawn uses `PlayerSpawnPoint`.
- **Dev tools** (`Assets/Editor/DevTools.cs`, the only Editor script; menu **Tools → Follow The Cat → Player**, greyed out outside Play mode, all through the game's own API): `Add 500 Coins`, `Give One Of Every Item` (ItemDatabase), `Full Heal`, `God Mode (until Play stops)` (long `StartInvincibility`, no Health change); **Town → Restore Next Building** (adds its coins + required item, `TryRestore`, saves). Use these instead of cheat values in assets. Removed 2026-11-15 at the developer's request: Reset Town, Open Scene shortcuts, SaveTools (Delete Save File: delete `save.json` in `Application.persistentDataPath` by hand, or New Game from the menu) and Astra's self-running asset builders (GuideCat, HealthPotion, KingWisp, SpeechBubble, LootVisual, OpeningCaveArt; the last one kept recreating the deleted `OpeningCave_Art` scene and prefab).

## Interaction

Adapted from MetrooDvania's `Scripts/Interaction` (`Scripts/Interaction/`):
- **IInteractable**: `CanInteract(player)` (false = refused, prompt still shows why), `GetPrompt(player)`, `Interact(player)`. Gets the `Player` so each one takes what it needs (Wallet, Inventory...).
- **PlayerInteractor** (on the Player, `player.playerInteractor`): `Refresh()` is called by `Player.Update` (like `EnemyDetection`); `OverlapCircle` at `facingDirection * searchOffset` on the `Interactable` layer (layer 8), nearest wins, none while dead. Exposes `currentTarget`, `promptText`, `canInteract`, `targetPosition`. `TryInteract()` is called by `PlayerState.HandleInteractInput()` from Idle, Walk and Run (E, `Interact` in the Player map).
- **InteractionPromptView** (scene object `InteractionPrompt`, world-space TMP): reads `PlayerInteractor` in `LateUpdate` and draws `[E] Talk`; refused prompts are red without the key. Never called by gameplay code.
- **NpcDialogue** (IInteractable): `speakerName`, `lines`, `lineDuration`; each interact shows the next line, after the last one (or the timer) it ends. Events `OnLineShown(speaker, line)`, `OnDialogueEnded`.
- **SpeechBubbleView** (on `CatSpeechBubble`/`MerchantSpeechBubble`): listens to its `NpcDialogue`, hides with the `CanvasGroup` (not `SetActive`, so it keeps listening).
- Scene: `GuideCat` (Interactable layer, trigger `CircleCollider2D`, `NpcDialogue`, `CatSpeechBubble` child). The cat's Talk animation isn't played yet.
- **Merchant** (`Scripts/Merchant/`, the object's only IInteractable): `Interact` stores the `customer` (Player), says the next `greeting` line (`NpcDialogue` on the `Greeting` child, no collider, so `GetComponentInParent<IInteractable>` can't pick it) and calls `ChangeState(GameState.Shop)`; never touches UI. Unlimited coins and stock. `TrySell(slotIndex)` sells the whole stack (`sellPrice` × amount, 0 = unsellable) via `Inventory.DeleteSlot` + `Wallet.Add`. `TryBuy(item)` buys one: item must be in `shopStock`, coins checked first, then `AddItemAndReturnAccepted` (0 = full, nothing changes), then `TrySpend`. Both return a `TradeResult` (Bought, Sold, NotEnoughCoins, InventoryFull, CannotSell, NotForSale) and fire `OnTrade(result, item, coins)`.
- **ShopStock** (SO, `ScriptableObjects/Merchant/MerchantStock_Tier1..3`): list of `ItemData`, `HasItem`. `Merchant.stockByTier` picks one by `TownProgress.townTier`; since 2026-11-15 every tier sells the Health Potion, Strength Elixir, Leather Armor and Wooden Club (tiers can still differ later). All four work.
- **Shop UI**: `MerchantStorePanel` (Astra's prefab, HUD child, `UIManager.merchantPanel`) has `MerchantStoreUI` (builds one `ShopEntry` prefab per stock item in `OnEnable`, `HorizontalLayoutGroup`) and `MerchantSellArea` (`IDropHandler`: a left-drag of an `InventorySlotUI` dropped anywhere on the panel → `TrySell`; right-drag ignored). `ShopEntryUI`: icon + `buyPrice`, `Button` click → owner → `TryBuy`. **ShopFeedbackUI** (`Scripts/UI/`, on MerchantStorePanel): listens to `Merchant.OnTrade`, shows `FeedbackText` under the panel for `showSeconds` (2, unscaled time: the shop pauses the game), gold on success, red on failure; message templates are Inspector strings (`{0}` item, `{1}` coins); plays `boughtSound` (ButtonClick), `soldSound` (ItemSold) or `failSound` (ButtonClick) SoundData on `HUD/UIClickAudio`. Its `merchant` is a Town scene override, like `MerchantStoreUI`'s.
- **MerchantAppearance** (on the Merchant prefab, art by Astra): one child Animator per town tier, follows `TownProgress.OnProgressChanged`; `Play`s Talk/Idle on the greeting's events (controllers have no transitions).

## Tutorial (GuideCat intro)

`Scripts/Tutorial/`. The intro is a chain of steps the GuideCat walks the player through (user's design: wake in a dark cave, take the lantern, the cat leads you out, tells the town's lore, the shop, the ruins, leads you to the dungeon, teaches combat and loot). The cat leads on foot; no skip; Continue returns to the current step's scene.
- **GuideStep** (SO, `ScriptableObjects/Tutorial/01_CaveWake` ... `10_DungeonLoot`): `sceneName`, `catPath` (GuideMarker IDs; he appears at the first when the scene loads and walks the rest), `leadsPlayer` (only walks while the player is within `leadDistance`; says his lines first), `followsPlayer` (after appearing he follows the player instead of walking a path: stays `followDistance` 1.5 away, runs at `runSpeed` 6 beyond `runDistance` 4, talks as soon as the player is close; the Dungeon steps 09/10 use it so the player never has to walk back to him), `lines`, `completion` (**GuideStepCompletion**: DialogueEnded, ItemPickedUp, ItemEquipped, ShopOpened, SceneEntered, EnemyKilled), optional `item` / `targetScene`. **TutorialSequence** (SO): the steps in order (only append once players have saves).
- **TutorialProgress** (ISaveable, on SaveSystem in Core): `stepIndex` (saved as `SaveData.tutorialStep`, save version 4; older saves count as finished), `currentStep`, `isFinished`, `TryComplete(completion, item)` (only the current step, matching item), event `OnStepChanged`. Completes SceneEntered steps itself when the scene is the target (in `Start` and after `Load`).
- **TutorialTriggers** (on SaveSystem; serialized `inventory`, `equipment`, `gameStateManager`: the components directly, because `Player` fills `playerInventory` etc. only in its own Awake, which can run after this OnEnable): listens only, reports to TutorialProgress: `Inventory.OnItemAdded` (new event) → ItemPickedUp, `Equipment.OnItemEquipped` → ItemEquipped, `GameStateManager.OnGameStateChanged(Shop)` → ShopOpened, `Enemy.OnAnyEnemyDied` (new static event) → EnemyKilled.
- **GuideCat** (`Prefabs/NPCs/GuideCat`, one in OpeningCave, Town, Outdoor, Dungeon under a `Guide` group; `progress`/`player` are scene references to the Core instance): shown only when the current step's scene is his scene (else Visual off and collider off); walks his path with `walkSpeed` (or follows, see `followsPlayer`), talks when the player is within `talkDistance` (after arriving, or first when leading or following), Talk/Walk/Idle facing via **GuideCatAnimator** (enum **GuideCatAnimationState** → cached hashes, like PlayerAnimator, plays only on change). Reports DialogueEnded. Uses NpcDialogue with `autoAdvance` (a line's timer shows the next line instead of ending; `SetLines` ends any conversation first). Prefab: root (Interactable layer, trigger CircleCollider2D 0.35, NpcDialogue "Cat", GuideCat) → `Visual` (Astra's GuideCat art + GuideCatAnimator; the art prefab's own placeholder bubble removed) and `CatSpeechBubble` (SpeechBubbleView wired to the root's NpcDialogue). `Prefabs/UI/Dialogue/CatSpeechBubble` was made 48 px taller upward (text box 320x114, four lines at size 23, auto-size 16–23 as a fallback); every tutorial line was measured to fit at full size. Keep new lines under about 95 characters. The box is see-through so the following cat doesn't hide the map: Background alpha 0.55, Border/TailBorder 0.6, Shadow 0.15; speaker name and text stay opaque (a text-only version without the box was tried and rejected).
- Step text: 02 tells both ways to equip (Tab + drag to the Weapon slot, or the hotbar number key); 10 also warns that the King Wisp appears on some visits (`BossSpawner.spawnChance` 0.5) and drops the Marble Stone the town needs.
- **GuideMarker** (`markerId`, `Find(id)`, like SpawnPoint) under `GuideMarkers` in each scene: Cave `CaveWake`, `CaveLantern`, `CavePath1..3`, `CaveExit`; Town `TownLore`, `TownMerchant`, `TownBuildings`, `TownPlaza`, `TownGate`; Outdoor `OutdoorStart`, `OutdoorPath1..4`, `OutdoorDungeon`; Dungeon `DungeonCat` (the old fixed-lines cat was replaced by the GuideCat prefab).
- **OpeningCave** scene (build index 1): Core instance, unpacked `OpeningCave_Art` (its staging cat, bubble, lantern and preview camera removed), `CaveWalls` EdgeCollider2D loop traced from Cave.png (64 px per unit), `PlayerSpawnPoint` at the wake point (also RespawnManager's), `Props/LanternPickup` (`Prefabs/Loot/LanternPickup`), `Exit/TownDoor` SceneDoor → Town `FromCave` (Town has `SpawnPoint_FromCave` on the plaza), StepStone footsteps. No real lighting yet (the warm patch is painted). Tested in Play mode from a fresh game (save backed up and restored): step 1 at start, cat shown and talking, lantern pickup → step 2, equip → step 3 and the Lantern is the weapon; Town/Outdoor/Dungeon with an old save: tutorial counts as done, cat hidden, no errors. The lead walks, the scene-change steps and the Dungeon steps still need a hand play-test (CLI Play mode doesn't advance frames).
- **New game**: Core's `Equipment.startingWeapon` is empty, so the Lantern from the cave is the first weapon. **MainMenuController**: New Game (asks "Start over?" once if a save exists, deletes it, loads `OpeningCave`), Continue (greyed without a save; loads the current step's scene, `Town` once finished; reads the save or its .bak), Settings, Exit. `SaveFile.DefaultFileName` is the one save slot name (SaveManager, menu, dev tools).

## Scenes and doors

No `DontDestroyOnLoad`: every game scene has its own copy of the `Core` prefab (Player, GameStateManager, HUD, EventSystem, SaveSystem, InteractionPrompt, cameras) and moves data through the save file.
Build list: `MainMenu` → `OpeningCave` → `Town` ⇄ `Outdoor` ⇄ `Dungeon`.
- **MainMenu** (no Core): Astra's `MainMenu` prefab on a Screen Space Overlay canvas; `MainMenuController` (New Game / Continue / Settings / Exit and the `?` controls panel, see Tutorial and the end of this file).
- **Town**: Merchant (shop), the three restorable buildings, later a rest spot. **Outdoor**: path between Town and Dungeon (TownDoor, DungeonDoor). **Dungeon** (was SampleScene): the painted shrine map (see Tilemaps), Wisps from `WispSpawner`, the BossSpawner, GuideCat; dying respawns at its `PlayerSpawnPoint`.
- Spawn IDs are named after where you came from: `FromOutdoor`, `FromTown`, `FromDungeon`. Outdoor uses the painted river crossing and permanent entrance prefabs described below.
- **SceneDoor** (`Scripts/Interaction/`, IInteractable): `SaveManager.Save()` (refuses to leave if it fails), then `SceneLoader.Load(targetScene, targetSpawnId)`. Blocked prompt if the scene isn't in the build list. Every door use is an autosave.
- **SceneLoader** (`Scripts/Core/`, static): keeps the spawn ID across the load (statics survive, scene objects don't).
- **SpawnPoint**: `spawnId` marker (`FromTown`, `FromOutdoor`, `FromDungeon`), `SpawnPoint.Find(id)`.
- **SceneArrival** (on SaveSystem): in `Start` takes the pending spawn ID and `Teleport`s the player there; the new scene's `SaveManager` loads health, coins and inventory in its own `Start`.
- Scene-only references (`Merchant` ↔ `GameStateManager`/shop UI, `RespawnManager.spawnPoint`) are overrides on each scene's Core instance.

## Tilemaps

The developer paints the maps with Unity's Tile Palette, using Astra's `Art/Map/ReferenceRuins128` kit (palettes `Ground128`, `Buildings128`, `Vegetation128`, `Water128`; 128 px = 1 cell). No other tile sets.
- **Ground sheet was repaired in place** (`Textures/Ground_128.png`, original in git before the repair commit): every tile had been made on its own, so neighbours never matched. Now all grass tiles share one average colour, and within 26 px of each tile border grass fades into one shared seamless grass texture and dirt into one shared dirt colour, so any tile can sit next to any tile. Stone, cliffs and flowers are untouched.
- The pre-drawn shapes (dirt crosses and blobs, stone paving, cliffs) are multi-cell **stamps**: box-select the whole shape in the palette and paint it as one piece. They are not autotiles; single cells of a path don't connect on their own.
- **Water sheet repaired in place**: plain water is colour-matched per depth row (light / mid / dark) and fades into one shared water texture at tile borders; shore tiles' grass uses the ground's grass colour and shared grass texture, so ponds and shores sit on the ground tiles. Waterfalls are stamps, untouched.
- **Vegetation sheet re-laid out in place**: the art had been assembled from 512 px blocks, so objects were clipped, had slits and leaked into their neighbours' cells. Every object (trees, stumps, logs, bushes, tufts, flowers, vines) now owns a block of whole cells: big ones centred on the bottom edge of a block as wide and tall as they need (a big tree is 4 x 5 cells), small ones centred in one cell. Box-select a block in the palette to stamp one clean object. Tile assets and the palette follow the new layout. Some trees keep a flat side where the art itself was clipped; a few bush halves sit in cells of their own.
- **Water small props** (rows 14+: lily pads, rocks, reeds, splashes) are one per cell too.
- `Buildings` sheet: alpha cleanup only; its pieces are still packed as Astra made them (stamps, or use the `CompleteObjects` prefabs).
- **Brushes** (`ReferenceRuins128/Brushes/`, palette `Brushes128`), all made from Astra's tiles: `Grass` (random plain grass), `Flowers` (random flower/tuft tiles), `Meadow` (grass with about 1 flower tile in 7); per water depth (`Light`, `Mid`, `Deep`): `Water…` (random, Grid collider), `Ripple…` and `Sparkle…` (Animated Tiles, 3 frames at 2 fps). Random brushes are Rule Tiles with a random output; drag or box-fill to cover an area.
- `ReferenceRuins128.spriteatlasv2` packs the four sheets with padding so tile edges don't bleed.
- Every tile has a collider shape (Ground/Water full cell, Buildings/Vegetation sprite outline); the **layer** decides if it blocks.
- **MapGrid template** (`Prefabs/Map/MapGrid.prefab`, 2026-11-14, empty): one 1-unit Grid with every layer set up once, for new maps: drag it into a scene and **unpack it** (Prefab → Unpack Completely) before painting; Unity 6's Tile Palette hides tilemaps that are part of a prefab instance (only "Create New Tilemap" shows). Order low → high: `Ground` -100, `GroundDetail` -90 (paths, decals), `Water` -80 (solid), `WaterDetail` -75 (ripples, lily pads), `Walls` -50 (solid), `Buildings` -45 (solid), `Vegetation` -40 (solid: trees, big bushes), `Decor` -35 (walk-through props), `Overhead` +10 (tree tops, roofs, arches drawn over the player). Solid = static Rigidbody2D + TilemapCollider2D + CompositeCollider2D copied from the old `Walls`, physics layer Default (so enemy line of sight is blocked too). **Outdoor now uses it** (unpacked `MapGrid` at 0,0; old `Grid` removed): Ground → Ground, Walls → Walls except its 91 water cells → Water, Decor → Decor (trees there stay walk-through), Ruins → Buildings; all 5,978 cells verified identical. `Art/Map/Grid.prefab` still holds the old Outdoor tiles and is only the base of the Dungeon's `Grid Variant`. Town keeps its own Grid.
- **Scene layers** (Town and Outdoor): `Grid` → `Ground` (order -100, no collision), `Walls` (order -50, `TilemapCollider2D` + `CompositeCollider2D` + static Rigidbody: anything painted here blocks), `Decor` (order -40).
- **Outdoor** has a 28 x 44 editable meadow with a winding central river. The Ground and Walls tilemaps contain the terrain, with animated ripple tiles in the river. The StoneBridge instance crosses the gap in water collision. Its Outdoor sprite faces north. The existing Decor tilemap holds Buildings128 and Vegetation128 stamps for the ruined tower, shrine, wall runs, and woods. Their blocking footprints are painted on Walls. TownGate at the southern trail end leads to Town and has a stepping-stone approach flanked by bushes. The northern DungeonEntrance has a fence-free 7.84-cell arch and nonblocking roots over a gradual corruption tint on Ground. New trail and bank tiles are in Art/Map/Outdoor/Terrain. The route between both entrances was checked against the serialized tile collision layout; Play mode unverified.

## Lighting

URP **2D Renderer** (`Settings/UniversalRP` → `Renderer2D`); sprites and tilemaps use Sprite-Lit-Default, so 2D lights affect them; UI is unaffected.
- **Darkness per scene** = its `Global Light 2D`: OpeningCave 0.18 (cool tint 0.6/0.65/0.85), Dungeon 0.32 (0.8/0.75/0.95; lowered from 0.45 for the atmosphere lights), Town and Outdoor 1 (daylight). All lights target every sorting layer (only `Default` exists).
- **LightFlicker** (`Scripts/Lighting/`, `[RequireComponent(Light2D)]`): wobbles a Light 2D around its Inspector intensity with Perlin noise (`flickerAmount`, `flickerSpeed`; random seed per light). Candles about 0.18 / 5, slow glows (abyss, portal) about 0.3 / 0.5.
- **Dungeon atmosphere** (2026-11-15, scene root `DungeonAtmosphere`, all placed from pixel positions on the painted map `LayeredShrine/Gemini_Generated_Image_...jpg`, 60 px per unit, which the developer put under `DungeonMap/Ground`): `PostProcessing` global Volume (`Settings/DungeonAtmosphere`: Bloom 0.85 / 1.1, Vignette 0.3; post-processing is switched on only on this scene's Core camera, an instance override); Global Light 2D 0.32; `Flames` (8 warm Point lights + flame particles on the stair torches, landing candles and shrine candles, statue halo, 3 green window glows), `Braziers` (3 green), `PortalGlow` + sparks, `Abyss` (10 slow green lights in the chasm + rising motes, order -50), `DustMotes` over the room, `Banners` (8 cut-outs `LayeredShrine/Banners/Banner_01..08.png` drawn one order above the map with `BannerWave.mat`). Shader `FollowTheCat/Banner Wave` (`Art/Map/Dungeon/BannerWave.shader`, lit sprite): shifts only strongly coloured (cloth) pixels, pinned at the top, zero at the cut-out's borders so it always lines up with the painting. Particles use `Art/VFX/GlowParticle.mat` (Sprite-Unlit + `SoftDot.png`). Alignment checked in an Editor render; lights, bloom and motion not seen in Play mode yet.
- **Dungeon painted-map occlusion** (2026-11-15): the developer's `EdgeCollider2D` (on `DungeonMap/Overhead/Map_Occluders`, whose old sprite renderer is switched off: it was cut from the earlier painting and did not line up) outlines the walkable floor. `LayeredShrine/Map_Occluders_Border.png` (same size as the map, child `Overhead/Map_Occluders_Border`, order 10, always on top) now follows the developer's painted mask (a see-through green tint over a smaller copy of the map = hides the player, orange = player on top; matched to the map at scale 1.2925 x 1.29375, offset 0/3 px, and read as 'greener than the original map', minus the Y-sorted MapProps); the first version was automatic: every pixel outside that outline with floor within 130 px above it (south walls) or 60 px beside it (side walls), except where floor lies within 85 px below (north walls: the player stands in front of those), plus the arena gate crown and the portal crown. `DungeonMap/MapProps`: the 3 shrine pillars, the pedestal and the 3 braziers as own sprites (`LayeredShrine/MapProps/`, pivot at the base, order 0, Y-sorted with characters, small capsule collider at the foot). If the collider outline changes, the border file must be cut again. Not seen in Play mode.
- **Shrine tile kit** (2026-11-15, `Art/Map/Dungeon/ShrineTiles/`): the painted shrine map cut into the 128 convention (128 px tiles, 128 PPU, centred pivots, 1-unit rectangular palettes made with `GridPaletteUtility`, manual cell 1 x 1). Three sheets resampled from the 60 px-per-unit map to 128 px per cell (5504 x 3712, max size 8192, compressed HQ), sliced through the Sprite Editor data provider, one Tile asset per non-empty cell, laid out in each palette exactly as on the map so shapes can be box-selected: `Shrine Ground` (495 tiles: all floor and stairs = inside the developer's collider outline), `Shrine Decor` (128: pillars, pedestal, braziers, banners, candle stands, fallen column), `Shrine Walls` (951: everything else: walls, rails, bridge and its arches, shrine building, arena wall, cliffs and abyss). The paint layers had been stretched by hand (2.38 x 4.11 / 3.81 x 3.49); they are back at scale 1 with their children kept in place, and the grid was shifted (0.83, 0.47) so the painted map's bottom-left corner sits on a cell corner (cell -52, -8): stamping a palette there lands exactly on the painting. Tile sizes verified; painting not tried by hand.
- **Light as item data**: `EquipmentData.lightRadius` (0 = none), `lightColor`, `lightIntensity`, `givesLight`. Lantern: radius 4.5, warm (1, 0.78, 0.45), intensity 2.2 (the cave art is painted dark, so light needs > 1 to show it).
- **LanternLight** (`Scripts/Player Scripts/`, on the Player's `LanternLight` child with a Point Light 2D, 0.6 up): listens to `Equipment.OnEquipmentChanged` (+=/-=), shows the held weapon's light (radius, inner = 35%, colour, intensity × the scene's darkness = 1 − its Global Light 2D intensity, read once in `Awake`; below 0.05 it stays off, so daylight Town/Outdoor show no lantern glow, the cave ≈ 82%, the Dungeon ≈ 55%) or turns it off; Perlin flicker (`flickerAmount` 0.08, `flickerSpeed` 3) in `Update`. ## Animation rules

- Each Animator Controller has no transitions; every state is a 4-direction blend tree on MoveX/MoveY, and the code picks the state with `Play` in the state's `Enter`.
- Animator state names must equal the enum value names (`Idle`, `Walk`, `Run`, `Windup`, `Attack`, `Hurt`, `Dead`, ...).
- One-shot clips (Attack, Windup, Hurt, Death) don't loop; looping clips are Idle, Walk, Run, Move.
- Clip lengths match their data timing (e.g. Windup = `windupTime`, player Attack = `attackDuration`, `destroyDelay` ≥ Death).

Rules:
- States decide **what/when**; components do **how**.
- Input checks, timers and transitions in `Update`; motor calls in `FixedUpdate`.
- Input → polled by states; game-state changes → events.
- Observer events for changes (`OnDamaged`, `OnDied`, later `OnMoneyChanged`, `OnWeaponChanged`, inventory `OnChanged`); UI only listens.
- Interfaces: `IDamageable`, `IDamageModifier`, `IPickable`, `IUsable`, `ISaveable`, `IInteractable`.
- ScriptableObjects for data: `CharacterData` → `EnemyData`; `ItemData` → `WeaponData`/`ArmorData` (slot enums); abstract `Ability` with cooldown.
- States referencing the concrete `Player`/`Enemy` is accepted coupling.

## Code review checklist

- Every `+=` has a matching `-=` (in `OnEnable`/`OnDisable`).
- No magic numbers in states; tunable values in the data ScriptableObjects or the Inspector.
- Private fields with `[SerializeField]`; read-only access via `{ get; private set; }`.
- `[RequireComponent]` where a component is needed.
- Consistent naming, correct spelling (scripts and asset names), class name matches file name.
- Naming (developer's choice, like Unity's own API): fields and properties camelCase, public ones too (`player.playerMotor`, `currentWeapon`, `isAlive`); types, methods, events (`OnDied`), enum values and constants (`const`, e.g. `HotbarSize`; never SCREAMING_CASE) PascalCase; `I` prefix only for interfaces.
- Same-GameObject components: `GetComponent` in `Awake` + `[RequireComponent]`, not serialized; serialize only references to other objects/assets.
- Delete dead code.
- Finish and test one system before starting the next; commit after each working step.
- When a system is finished, update this file in the same step.
